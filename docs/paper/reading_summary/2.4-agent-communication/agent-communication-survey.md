# 2.4 Agent 间通信范式综述：从自然语言到权重空间

**报告日期**：2026年6月10日
**面向章节**：论文 §2.4

---

## 摘要

系统梳理多智能体通信三大范式演进：**自然语言文本（1.0）→ 结构化消息/共享记忆（2.0）→ 权重空间通信（3.0）**。核心发现：

1. NL 通信灵活性高，但受制于"通证税"——每次交互触发 LLM 推理，Token 消耗和延迟构成根本瓶颈
2. A2A/ANP 协议在传输层提升了互操作性，但无法解决内容层（NL 推理）的效率问题
3. TFlow 提出将通信负载从上下文迁移至参数，以权重扰动替代文本对话，是颠覆性但早期的方案
4. 《The Vision Wormhole》等潜在空间通信工作独立验证了这一方向
5. TFlow 的局限性（固定拓扑、扰动稳定性、可解释性、异构兼容性）构成研究空白

---

## 1. 引言

多智能体系统中，通信是集体智能的基石也是瓶颈。NL 通信直观灵活，但每次交互都是一次 LLM 推理——"通证税"（Token Tax）构成了 MA 规模化的主要障碍。

---

## 2. 三大主流通信范式

### 2.1 自然语言文本（范式 1.0）

Agent 直接通过 NL 对话协作。优势：灵活性、表达能力、LLM 原生支持。代价：Token 成本高、语义歧义、延迟大。

| 代表工作 | 机制 |
|---------|------|
| **CAMEL** (2023) | 角色扮演，Inception-prompting，两 Agent 对话完成复杂任务 |
| **AutoGen** (2023) | 微软，多角色群聊，动态决定对话流程 |

### 2.2 结构化消息（范式 2.0）

信息封装为预定义 Schema（JSON/XML），降低解析成本，提升互操作性。但内容主体仍多为 NL。

| 代表工作 | 机制 |
|---------|------|
| **Google A2A** (2024) | HTTP/JSON-RPC 2.0，Agent 发现、能力协商、任务管理 |
| **ANP** | 社区驱动，去中心化身份（DID）、语义发现、端到端加密 |
| **Message Graphs** | 图神经网络处理 Agent 结构化消息流 |

### 2.3 共享记忆/黑板模型（范式 2.0 变体）

Agent 不直接发消息，而是异步读写公共数据空间。解耦生产者和消费者。

| 代表工作 | 机制 |
|---------|------|
| **MARBLE / A-Mem** (2025) | 共享记忆模块，支持跨 Agent 长期信息检索 |
| **G-Memory** (2025) | 层级化结构共享记忆 |
| **Blackboard 架构复兴** (2025) | 经典 AI 架构在 LLM 时代的重新引入 |

## 3. 新兴范式：权重空间通信（范式 3.0）

### 3.1 核心思想

将通信负载从**上下文空间**迁移至**参数空间**。发送方不生成文本，而是为接收方实时编译低秩权重扰动（LoRA 形式），接收方动态加载后行为被改变——"瞬态微调"替代对话。

### 3.2 支撑逻辑

- 现有范式根瓶颈：所有信息必须进入 LLM 上下文 → 每次都要完整前向传播
- 参数化知识优势：一次修改权重，后续推理零额外开销
- 用"模型手术"替代"对话治疗"，通信效率数量级提升

### 3.3 TFlow（Thought Flow）

首个明确实现权重空间通信的工作：

- 发送方根据自身 hidden state 编译接收方特定的低秩扰动
- 接收方动态加载 → 完成任务 → 丢弃
- 声称在协作 QA 和软件工程基准上超越 SOTA 文本方法

### 3.4 潜在局限

1. **固定拓扑**：依赖预定义通信网络，发送方数量扩展时扰动叠加稳定性未知
2. **可解释性差**：权重扰动是高维数值矩阵，语义模糊，调试审计困难
3. **异构模型兼容性**：要求发送方理解接收方内部架构
4. **表达能力**：能否传递复杂逻辑/创造性思想，尚待验证

### 3.5 旁证：潜在空间通信

**《The Vision Wormhole: Latent-Space Communication in Heterogeneous Multi-Agent Systems》**独立验证了"非符号化通信"方向。标题强调"异构"——直接触及 TFlow 最大挑战，可能提出了跨架构的潜在空间转换机制。

**结论**：存在 TFlow 以外的权重/潜在空间通信工作，该方向非孤例，代表了未来趋势。

## 4. A2A 协议与效率瓶颈

### 4.1 标准化努力

| 协议 | 定位 | 核心技术 |
|------|------|---------|
| Google A2A | 企业内部协作标准 | HTTPS + JSON-RPC 2.0 + SSE |
| ANP | 开放网络"智能体互联网" | DID + 语义发现 + E2E 加密 |

### 4.2 效率瓶颈论证

**A2A 协议层面已意识到效率问题**，但优化集中在传输层（轻量协议、缓存）。社区明确指出：

- MCP 和 A2A 采用 NL 通信 → "浪费大量 token，成本极高"
- "代理爆炸"问题：Agent 过度细分 → 通信开销巨大 → 每次"上下文切换"都是昂贵的 LLM 重新解释
- **矛盾**：传输层追求效率，内容层（NL）却无法绕过根本瓶颈

这正是 TFlow 的核心靶点——不是优化"对话"的传输，而是**取消"对话"**。

## 5. 范式演进总结

| | 范式 1.0 NL | 范式 2.0 结构化 | 范式 3.0 权重空间 |
|--|-----------|---------------|-----------------|
| 灵活性 | 极高 | 中-高 | 低（早期） |
| 通信成本 | 极高（Token Tax） | 中-高 | 理论极低 |
| 可解释性 | 高 | 中-高 | 极低 |
| 成熟度 | 成熟 | 快速发展 | 早期探索 |
