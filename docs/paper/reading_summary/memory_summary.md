## PEAM 论文阅读总结

**论文链接**：https://arxiv.org/pdf/2605.27762

### 一、值得关注的点

1. **双系统架构**：慢速 GPT‑4o 探索+快速 MoE‑LoRA 执行，将"学习/探索"与"固化/执行"解耦。
2. **失败作为训练信号**：构建"失败-校正"轨迹对，用 DPO 让模型从错误中修正，不仅仅是文本反思。
3. **BC+DPO 联合**：BC 保证生成代码的语法格式正确性（函数包装器），DPO 提供动作序列的偏好。纯 DPO 无法生成可执行代码（0/12），BC+DPO 达到 12/12。
4. **PV 多维评分**：综合成本、稳定性、冗余度、类别冲突四个维度，决定哪些经验值得固化，优于简单启发式（成功率+频率）。
5. **STC 统计触发**：基于技能自身失败率的历史基线做 Z 检验，不依赖绝对阈值，可跨任务分布迁移。
6. **物理隔离 MoE**：每个技能类别独立 LoRA 适配器，参数不共享，结构级抗遗忘。

### 二、存疑的点

1. **消融实验 A2 参数量不对等**：
   - PEAM（MoE 隔离）：3 个适配器 × ~83M = ~250M
   - 消融 A2（单共享 LoRA）：1 个适配器 × ~83M = ~83M
   - 遗忘差异（0% vs 32.4%）无法区分是"参数共享导致的干扰"还是"总容量不足导致的挤压"。
2. **PV 权重固定**：通过网格搜索固定，未评估不同环境下最优权重的变化，泛化性存疑。

### 三、对 Agent 记忆 / 上下文摘要的启发

1. **记忆分层**：慢速探索 → 情景暂存 → 参数固化，比单一 RAG 或摘要更接近"工作记忆 → 长期记忆"模型。
2. **固化比检索更高效**：将高频技能固化为 LoRA 参数，token 减少 85%，延迟降低 42%，适合边缘部署。
3. **"什么值得记住"需要智能筛选**：PV 提供可计算的准入标准，避免垃圾进垃圾出。
4. **上下文摘要可被替代**：传统摘要是 token‑level 记忆，PEAM 将关键信息压入权重，实现真正的"内化"。
5. **抗遗忘需要结构保证**：物理隔离（per‑task/per‑category LoRA）比正则化或重放更直接可靠。

### 四、后续实验方向

1. **容量对齐消融**（**存疑**：论文未提供准确参数，实际需根据模型维度重新计算）：
   - 将单共享 LoRA 的总参数量提升至与 MoE 隔离方案相当
   - 或将每个隔离 LoRA 的参数量压缩至与单共享 LoRA 相当
   - 比较遗忘率，区分"容量不足"与"参数共享干扰"
2. **不同领域的 PV 适应性**：在 Web Agent、代码生成等场景重新搜索 PV 权重。
3. **对比 STC 与学习型触发器**：用 RL 学习固化时机，与 STC 对比。
4. **与纯 RAG 系统端到端对比**：对比 PEAM 与 MemGPT、RAPTOR 等强基线。

## TMEM 论文阅读总结

### 一、核心思想

1. **触发机制**：上下文长度（工作上下文+显式记忆）超过预设阈值（LoCoMo 用 4096 tokens，LongMemEval-S 用 12288 等），且还没输出最终答案，就触发"记忆写入"。
2. **知识组织形式**：用一个固定提示让模型输出 JSON 格式的 QA 对（`{"instruction": 问题, "output": "答案"}`），问题必须能在当前会话中找到依据。
3. **知识存储位置**：不是存成文本塞回上下文，而是用这些 QA 对做**在线 SFT**，更新 LoRA 的 **B 矩阵**（A 由 SVD 初始化后冻结）。
   - 只更新**最后 4 层的 FFN 投影**（gate/up/down_proj），注意力层不动。
   - 秩 r=6，参数量很小。
4. **生效方式**：更新后的 B 会立刻影响**同一回合后续**的动作采样（因为策略变成 π_{θ₀+BA}），工作上下文被清空但参数里的记忆保留。
5. **跨触发累积**：同回合多次触发，B 会累加更新，不重置。

### 二、存疑的点

1. **B 的大小（r=6）**：论文没做 r 的消融，不知道 r=1/2/4/8 的表现。会不会太大增加开销、太小表达能力不够？
2. **在线 SFT 开销**：论文给了总的时间/显存对比，但没有单独拆解"生成 QA 对"和"SGD 几步更新"各自花了多少。触发频繁时累积开销能不能接受？
3. **异步可行性**：论文是同步阻塞的（触发→提取→更新→清空上下文→继续）。实际上没必要阻塞，可以后台更新 B，主线程先用旧策略顶着，下次触发再换新的。这个设计论文没做。

### 三、对 Agent 记忆 / 上下文压缩的启发

- LoRA 可以**替代 in-context learning**：把知识压进参数，而不是每次拼接到提示里。
- 会话内更新是好的，但不一定非得阻塞；异步更新更实用。
- 一个值得做的实验：**在总计算开销（时间/tokens）一致的前提下**，对比"参数内化（TMEM）" vs "外挂摘要（MemAgent 风格）"，看看谁更有效。
  - 可以扫一下 r=1,2,4,6,8 的性能曲线，找到性价比最高的 r。
  - 也可以把摘要占用的 token 数折算成成本，与 TMEM 的更新开销对齐再比。
