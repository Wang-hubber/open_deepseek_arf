## 一、论文阅读

### PEAM

**论文链接**：https://arxiv.org/pdf/2605.27762

**值得关注的点**

1. **双系统架构**：慢速 GPT‑4o 探索+快速 MoE‑LoRA 执行，将"学习/探索"与"固化/执行"解耦。
2. **失败作为训练信号**：构建"失败-校正"轨迹对，用 DPO 让模型从错误中修正，不仅仅是文本反思。
3. **BC+DPO 联合**：BC 保证生成代码的语法格式正确性（函数包装器），DPO 提供动作序列的偏好。纯 DPO 无法生成可执行代码（0/12），BC+DPO 达到 12/12。
4. **PV 多维评分**：综合成本、稳定性、冗余度、类别冲突四个维度，决定哪些经验值得固化，优于简单启发式（成功率+频率）。
5. **STC 统计触发**：基于技能自身失败率的历史基线做 Z 检验，不依赖绝对阈值，可跨任务分布迁移。
6. **物理隔离 MoE**：每个技能类别独立 LoRA 适配器，参数不共享，结构级抗遗忘。

**存疑的点**

1. **消融实验 A2 参数量不对等**：
   - PEAM（MoE 隔离）：3 个适配器 × ~83M = ~250M
   - 消融 A2（单共享 LoRA）：1 个适配器 × ~83M = ~83M
   - 遗忘差异（0% vs 32.4%）无法区分是"参数共享导致的干扰"还是"总容量不足导致的挤压"。
2. **PV 权重固定**：通过网格搜索固定，未评估不同环境下最优权重的变化，泛化性存疑。

### TMEM

**核心思想**

1. **触发机制**：上下文长度（工作上下文+显式记忆）超过预设阈值（LoCoMo 用 4096 tokens，LongMemEval-S 用 12288 等），且还没输出最终答案，就触发"记忆写入"。
2. **知识组织形式**：用一个固定提示让模型输出 JSON 格式的 QA 对（`{"instruction": 问题, "output": "答案"}`），问题必须能在当前会话中找到依据。
3. **知识存储位置**：不是存成文本塞回上下文，而是用这些 QA 对做**在线 SFT**，更新 LoRA 的 **B 矩阵**（A 由 SVD 初始化后冻结）。
   - 只更新**最后 4 层的 FFN 投影**（gate/up/down_proj），注意力层不动。
   - 秩 r=6，参数量很小。
4. **生效方式**：更新后的 B 会立刻影响**同一回合后续**的动作采样（因为策略变成 π_{θ₀+BA}），工作上下文被清空但参数里的记忆保留。
5. **跨触发累积**：同回合多次触发，B 会累加更新，不重置。

**存疑的点**

1. **B 的大小（r=6）**：论文没做 r 的消融，不知道 r=1/2/4/8 的表现。会不会太大增加开销、太小表达能力不够？
2. **在线 SFT 开销**：论文给了总的时间/显存对比，但没有单独拆解"生成 QA 对"和"SGD 几步更新"各自花了多少。触发频繁时累积开销能不能接受？
3. **异步可行性**：论文是同步阻塞的（触发→提取→更新→清空上下文→继续）。实际上没必要阻塞，可以后台更新 B，主线程先用旧策略顶着，下次触发再换新的。这个设计论文没做。

## 二、核心发现

### 1. 记忆演进的两种范式
- **旧范式（外挂摘要 + in‑context learning）**：记忆是文本，塞回上下文，每次重新计算 KV，有损压缩，且策略本身不变化。
- **新范式（参数化记忆 + LoRA）**：记忆是权重增量，写入 FFN 的低秩矩阵，不占上下文，推理时自动生效，策略可以实时演化。

TMEM 和 PEAM 分别从"会话内在线更新"和"跨回合技能固化"两个角度验证了参数化记忆的有效性。

### 2. 关键机制
- **更新时机**：上下文达到截断长度时触发（TMEM），或基于失败率统计触发（PEAM 的 STC）。
- **知识组织形式**：QA 对（TMEM）或成功/失败‑校正轨迹对（PEAM）作为监督信号。
- **更新方式**：在线 SFT（仅更新 LoRA 的 B 矩阵，A 固定），只改最后几层 FFN，参数量极小。
- **知识存储位置**：从提示空间迁移到参数空间（FFN 的权重扰动）。

### 3. 消融实验的局限
- PEAM 的 MoE vs 单 LoRA 消融中，总参数量不对等（250M vs 83M），无法区分"参数共享干扰"与"容量不足"。
- TMEM 未对 LoRA 秩 r 做消融，r=6 是经验值，缺乏权衡曲线。
- 两类论文都没有拆解"生成监督信号"与"梯度更新"的各自开销。

### 4. 偏好记忆 vs 事实记忆
- 偏好（统计规律）适合自监督更新。
- 事实（须忠于原文）需要强监督（如 QA 对）+ 验证机制。
- 两者可以分开管理，用不同 LoRA 适配器或不同更新策略。

## 三、下一步思想 / 实验方向

### 1. 统一外部数据的参数化存储框架
把系统提示词、会话上下文压缩、长期记忆、垂直领域知识都视为"外部数据"，各自对应一个可插拔的 LoRA 适配器。设计：
- 一个路由机制（简单的分类器或规则）根据当前任务选择加载哪些适配器。
- 不同的更新策略（触发条件、更新频率、监督信号来源）。
- 偏好记忆用自监督（如从历史中聚类重复模式），事实记忆用强监督（如用户反馈或可验证的 QA 对）。

### 2. 消融实验：容量对齐下对比参数内化 vs 外挂摘要
- 控制总计算开销（时间 / token 数）相同，比较 LoRA（不同秩 r）和文本摘要（不同长度）在长对话/多轮任务中的表现。
- 扫 r=1,2,4,6,8，找到性价比最高的 r。
- 同时比较"生成监督信号 + 更新 B"的总时间 vs 纯摘要的生成时间。

### 3. 异步非阻塞更新
- TMEM 是同步阻塞的（触发→生成 QA→更新→清空→继续）。实际工程中可以改为：后台 worker 执行 SFT 更新，主线程先用旧策略继续，下次触发时切换新权重。
- 设计一个双缓冲机制（当前 B 和后台 B），更新完成后原子切换。

### 4. 把 PV 和 STC 的思想迁移到通用 Agent
- PV（参数化价值）：设计一套面向通用 Agent 的"值得记忆"评分维度，例如：访问频率、事实一致性、与已有记忆的冲突度、时效性、可验证性。
- STC（自触发固化）：基于失败率或不确定性统计（如置信度低于阈值）自动触发记忆更新，无需手工设定阈值。

### 5. 偏好与事实解耦的实现方案
- 两个独立的 LoRA 适配器（或一个 MoE 的两个专家）：一个用自监督（如 online 聚类）更新，一个用强监督（如可校验的 QA 对）更新。
- 推理时，路由同时激活两者（加法组合）或根据上下文选择性激活。
