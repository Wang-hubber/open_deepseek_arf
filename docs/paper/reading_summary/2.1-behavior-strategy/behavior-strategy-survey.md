# 2.1 Agent 行为策略：从外部编排到内生选择

**报告日期：** 2026年6月10日
**面向章节：** 论文 §2.1

---

## 摘要

本报告由两阶段研究整合而成：

**第一阶段 — 主流范式与 Harness 批判**：系统性梳理 2023–2026 年间三大 Agent 架构范式（ReAct、Plan-and-Execute、Multi-Agent），并指出现有综述的核心认知盲区——将 Harness/框架层碎片化归入"工具""记忆"等模块，缺乏将其作为第一性架构维度的系统性分析。对"厚 Harness"过载的批判已在从业者社区形成共识：架构方向应从"框架驱动的认知"向"模型驱动的认知"演进。

**第二阶段 — 内生策略选择**：在确立策略谱系后，追问一个更深层的问题——Agent 能否摆脱外部硬编码编排，根据任务动态特征（复杂度、不确定性、环境反馈）自主选择最合适的行为策略？研究发现两条主要技术路径：（1）**元控制器（Meta-Controller）架构**——通过小型 Transformer 策略网络动态调度底层行为策略；（2）**基于强化学习与元学习的自适应机制**——将策略选择本身建模为 RL 问题。2025–2026 年间，Google DeepMind、OpenAI、Anthropic 各自采用不同技术路线探索策略自适应的商业化落地。

核心结论：Agent 研究正经历从"如何执行特定策略"到"如何选择策略"的认知升级，这是迈向更高阶自主智能的关键一步。

## 1. 主流 Agent 行为策略及其局限性

### 1.1 ReAct：推理与行动的动态交织

核心思想：将推理（Reasoning）与行动（Acting）紧密结合，形成"思考-行动-观察"闭环，模仿人类"边想边做"的模式 [[2]][[3]][[4]]。每一步行动前生成自然语言推理轨迹，用于分析现状、分解问题、制定下一步计划或修正错误 [[16]]。

- **奠基论文**：Yao et al., "ReAct: Synergizing Reasoning and Acting in Language Models", ICLR 2023
- **优势**：动态适应性（根据实时外部反馈调整策略）、可解释性（每一步有思考轨迹）、处理复杂多步任务的能力 [[20]][[21]][[22]][[23]]
- **局限**：
  - 累积错误与幻觉风险——链式结构使某一步推理偏差可能传播至后续循环 [[26]]
  - 效率与成本——每个 Think-Act 循环需至少一次 LLM 调用，长步骤任务延迟高、成本高 [[28]]
  - 对即时反馈的依赖——反馈模糊或延迟时决策调整能力大打折扣
- **关键设计洞察**：稀疏思考策略——在决策制定类任务中，思考只需稀疏地出现在关键节点（子目标切换、异常处理），而非每步强制生成，一定程度上缓解了长轨迹下的 Token 开销问题
- **存疑**：稀疏思考的触发条件未明确，实践中的稀疏程度高度依赖人工示例分布，可能在不同任务间泛化不稳定；步数上限缺乏自适应依据

### 1.2 Reflection / Reflexion：从失败中学习的智者

单纯的 ReAct 缺乏跨任务周期的长期记忆和学习能力。Reflection 机制赋予 Agent 事后复盘和自我批评的能力，本质上是"对推理的推理"（reasoning about reasoning）[[29]][[30]]。

- **奠基论文**：Shinn et al., "Reflexion: Language Agents with Verbal Reinforcement Learning", NeurIPS 2024
- **工作机制**：当 Agent 完成一次任务尝试后，启动反思过程——回顾整个执行轨迹，生成结构化"反思文本"，总结失败原因并提炼策略性建议。这些反思存储在长期记忆库中，后续任务规划时检索相关反思内容 [[31]][[32]][[33]]
- **优势**：
  - 实现自我改进——将失败经验转化为可操作指导，无需重新训练模型权重 [[34]][[35]]
  - 增强长期规划能力——建立跨任务的策略知识 [[36]]
  - 轻量级——通过操作记忆（反思文本）而非更新模型权重实现学习
- **局限**：
  - 事后诸葛亮——本质上是事后分析，无法在任务执行过程中实时干预决策
  - 反思质量依赖——LLM 生成的反思过于笼统或错误，则改进无从谈起
  - 触发时机问题——何时启动反思？每次失败后都反思增加额外计算开销

### 1.3 Plan-and-Execute：谋定后动的战略家

与 ReAct 的即时反应不同，该范式体现"谋定而后动"思想，适合目标明确、步骤清晰、环境变化可预测的任务 [[37]][[38]]。

- **奠基论文**：Wang et al., "Plan-and-Solve Prompting", ACL 2023
- **工作机制**：分为两个截然不同的阶段——规划阶段（一次性对整个任务进行全面分析，生成有序行动列表）→ 执行阶段（严格按照预设计划逐步执行，通常不动态重规划）[[11]][[12]]
- **优势**：结构清晰、目标导向；成本可控（规划阶段仅需少数 LLM 调用）[[39]]
- **局限**：
  - 缺乏适应性——一旦环境发生未预料变化或某一步骤失败，整个预设计划可能完全失效 [[40]]
  - 对任务先验知识要求高——存在大量不确定性时难以制定完美初始计划
- **关键设计洞察**：PS+ 的精细化指令设计——添加"提取相关变量及其对应数字""计算中间结果"等指令，在六个数学推理数据集上平均准确率（76.7%）显著优于零样本 CoT（70.4%）
- **存疑**：内生性 PS 的可行性——CoT 所需的逐步推理在预训练语料中广泛存在，而"先写计划再执行"的显式结构在自然文本中相对稀缺，PS 更可能以"分化"而非"涌现"方式出现

### 1.4 Multi-Agent：通过协作涌现复杂智能

当单一 Agent 能力不足以应对复杂目标时，通过多个专门化 Agent 协作来完成 [[58]][[59]]。

- **代表框架**：
  - **AutoGen**（Wu et al., 2023）：可对话智能体统一抽象 + 动态群组对话 + LLM 选择发言者
  - **MetaGPT**（Hong et al., 2023）：工程管理 SOP 编码为提示序列 + 结构化发布-订阅通信协议
- **优势**：可扩展性强，处理高阶复杂任务；角色分工消融实验显示逐步添加 PM、架构师、项目经理可将可执行性从 1.0 升至 4.0（满分）
- **局限**：
  - 编排复杂度高——通信设计、冲突解决、资源分配 [[58]]
  - AutoGen 的群组广播模式存在上下文爆炸风险，步骤超过 40 步时缺乏优化策略
  - MetaGPT 的订阅机制基于静态预定义规则，缺乏动态自适应能力
  - 结构化文档模板深度绑定软件开发，跨领域泛化需人工重新设计数据模式
- **两种通信思路**：AutoGen 的自然语言对话 vs MetaGPT 的结构化消息——这一对比直接呼应论文 §2.5 Agent 通信范式的演进路线

### 1.5 策略选择的困境：为何内生选择至关重要？

通过上述分析，一个清晰的事实浮现：**没有一种策略是万能的**。

| | ReAct | Reflection | Plan-and-Execute | Multi-Agent |
|---|---|---|---|---|
| 优势场景 | 高度动态、充满不确定性的探索性任务 | 需要跨任务学习、避免重复错误的试错场景 | 流程固定、环境可预测的结构化任务 | 单 Agent 能力不足的复杂目标 |
| 核心弱点 | 成本高、错误累积 | 事后分析、无法实时干预 | 僵化、缺乏适应性 | 编排复杂、通信开销大 |
| 决策成本 | 高（多次 LLM 调用） | 中（额外反思调用） | 低（少量规划调用） | 高（多 Agent 并发） |

当前，决定使用哪种策略的"元决策"（meta-decision）仍由人类开发者承担。这种外部编排方式迫使我们在任务开始前做出静态的、往往是次优的选择——可能为简单任务配置昂贵的 ReAct+Reflection，或让需要灵活探索的任务死板执行 Plan-and-Execute 计划而最终失败。

因此，实现策略选择的内生化——让 Agent 自身成为一个能够审时度势的"战略家"，根据任务实时需求从"策略工具箱"中动态选择——是其迈向更高自主性和通用性的必然要求。

## 2. 隐形维度：Harness / 框架层

### 2.1 Harness 的五大核心功能

现有 Agent 综述倾向于将框架功能碎片化归入不同模块，但 Harness 本身是独立的第一性架构维度：

| 功能 | 职责 |
|------|------|
| 编排循环 | 驱动任务流程——ReAct 的 Think-Act-Observe 循环，或 Plan-Execute 的二阶段执行 |
| 工具调用 | 解析 LLM 工具请求 → 执行 → 格式化结果返回 |
| 记忆管理 | 短期（对话历史）和长期（向量 DB 检索 / Reflection 反思文本）记忆的读写 |
| 上下文管理 | 动态构建 Prompt（系统指令 + 任务 + 记忆 + 工具输出），控制窗口长度 |
| 安全与成本 | 行为监控、权限门控、Token 追踪 |

从 ARF 视角看，`ControlPlane` + `LoopStrategy` 抽象的设计动机正是：框架不应绑定单一循环模式或通信协议，而应支持按任务特征动态选择或组合。

### 2.2 现有综述的认知盲区

现有综述将 Harness 功能**碎片化**归入"规划""记忆""工具使用"等独立模块，导致三个问题：

1. **忽视 Harness 的整体性与协同性**——各组件高度互联，分拆讨论丧失对"操作系统"层面设计哲学的理解
2. **模糊模型与框架的责任边界**——无法清晰界定哪些认知由 LLM 完成，哪些由框架代理
3. **阻碍跨框架深度比较**——无法讨论 Harness 的"厚度"差异（LangChain vs LangGraph vs Claude Code 的架构哲学差异）

**关键 Gap：缺乏将 Harness 作为第一性架构维度的系统性分析。**

### 2.3 "厚 Harness" 批判

**"大模型 vs 大框架"的张力**：

- **大框架路线**（2023–2024 主流）：LLM 是认知引擎但缺乏结构化能力，需要复杂外骨骼（状态跟踪、错误处理、工具调度）
- **大模型路线**（2025+）：模型能力指数增长（百万 Token 窗口、原生工具调用）→ 认知负载应推回模型内部，Harness 应变薄

**功能过载的四个批判维度**：

1. **设计假设问题**：Anthropic 工程师指出 "Harness 里的每个组件，都在假设'模型自己做不到这个'"——建立在模型不信任假设上的设计
2. **过度工程化与脆弱性**：大量胶水代码、规则驱动的复杂逻辑 → 难以适应任务变化、难以调试
3. **掩盖模型真实能力**：厚 Harness 可能"代劳"模型 → 难以区分是模型强还是框架工程强
4. **技术债务累积**：基于旧模型局限性设计的 Harness（如 8K 窗口的记忆压缩模块）在 1M 上下文窗口模型面前成为性能瓶颈

**架构方向**：从"框架驱动的认知"→ "模型驱动的认知"——这与 §1.5 提出的内生策略选择诉求高度一致：策略选择的决策权应从 Harness 的硬编码规则转移到模型的内生能力中。

## 3. 内生策略选择：新兴的技术路径与研究前沿

在 2025 年至 2026 年上半年，学术界和领先 AI 实验室在推动 Agent 策略选择内生化方面取得了显著进展。研究路径逐渐清晰，主要集中在两条技术路线：**元控制器（Meta-Controller）架构**和**基于强化学习与元学习的自适应机制**。

### 3.1 "元控制器" (Meta-Controller) 架构：Agent 大脑中的指挥官

元控制器架构的核心思想是在标准 LLM Agent 认知回路之上增加一个更高层次的决策单元。这个"元控制器"不负责具体任务执行，而是监控战场态势（任务上下文），向下属"兵种"（不同行为策略）下达指令 [[42]][[43]]。

**输入**：
- 任务描述与复杂度评估（简单查询 vs 多步操作 vs 开放探索）
- Agent 内部状态（信念、执行历史、失败次数）
- 环境反馈特征（成功、特定错误码、模糊结果）

**输出**：决策信号——激活、切换或调整底层行为策略（如"激活 ReAct 循环""执行 Plan-and-Execute 计划""启动 Reflection 模块"）

**关键研究案例 — Meta-Adaptive Context Engineering** [[44]][[45]]：

一篇于 2025 年末引起广泛关注的研究报告为元控制器的实现提供了具体技术蓝图：

- **架构**：1200 万参数的小型 Transformer 策略网络作为元控制器
- **输入**：任务初始指令 + 复杂度初步评估
- **输出**："策略分配向量"——决定采用哪种或哪几种策略组合（最小上下文 → 完整历史反思 → 测试时计算）
- **训练**：采用**元强化学习（Meta-Reinforcement Learning）**，使用 **Group Relative Policy Optimization (GRPO)** 算法
- **奖励函数**：平衡三个核心目标——**任务准确性**、**计算成本**（以 Token 数量衡量）、**决策置信度校准**

这项研究的开创性在于：证明了一个小型、经过元强化学习训练的元控制器，能够学会根据任务内在属性，在不同"思考深度"和"资源消耗"的策略间做出明智权衡。

**其他元推理方法**：
- **Meta-Reasoner** [[47]][[48]]：通过元推理模块，为 LLM 动态选择最佳推理路径（直接生成 vs 复杂 CoT）
- **MRP (Meta-Reasoning Prompt)**（微软研究院）[[49]]：通过提示工程引导模型进行元层面策略选择

### 3.2 基于强化学习与元学习的自适应选择

与显式构建元控制器不同，此路径将策略选择问题直接建模为强化学习（RL）问题 [[50]]：

- **状态（State）**：任务当前描述、执行历史、环境反馈等
- **动作（Action）**：选择宏观行为策略，如 `select_react()`, `select_plan_execute()`, `select_reflection()`
- **奖励（Reward）**：任务成功率、执行效率（时间/成本）、解决质量

通过 RL 算法（Q-Learning, PPO 等），Agent 学习函数 `π(action|state)`——这是基于历史经验优化的结果，而非硬编码规则。

**关键研究案例**：

- **RAISE 框架**（2025 年 10 月）[[50]]：使用 RL 动态选择最优指令集进行模型微调，证明了"通过 RL 让模型学会选择"这条技术路径的可行性。可将"指令"概念泛化为"行为策略"
- **ReMA**（预印本）[[51]]：标题揭示使用**多智能体强化学习（MARL）**让 LLM 学会"元思考"——不同 Agent 代表不同策略，通过协作和竞争共同学习如何在复杂任务中动态组合和切换策略
- **元强化学习（Meta-RL）** [[52]]：旨在学习一种能快速适应新任务的"如何选择策略"的元技能——面对全新任务时能迅速泛化，做出合理策略判断

### 3.3 混合与分层框架

不追求单一"最优"选择，而是动态组合和切换策略。

**策略融合与动态切换** [[53]][[54]]：

有研究指出，与其在 ReAct 和 Plan-and-Execute 之间做非此即彼的选择，不如将它们结合——Agent 先用 Plan-and-Execute 生成高层计划框架，执行每个高层步骤时使用 ReAct 循环处理该步骤内的具体细节和不确定性。一个于 2025 年提出的自适应推理策略选择器模型，能够根据任务实时复杂度在 **Direct**、**ReAct** 和 **Plan-and-Execute** 三种策略间动态切换。

**内省驱动规划（Introspection-Driven Planning）** [[55]]：

强调 Agent 在规划和执行过程中进行持续自我审视。当通过内省发现当前策略可能无法达成目标，或环境变化超出当前策略应对范围时，触发"内省干预"——重新评估并切换到更合适的策略。这本质上是将 Reflection 机制从"事后"提前到"事中"，使其更加主动和及时。

### 3.4 与 §2 Harness 层的关系

内生策略选择直接回应了 §2.3 提出的"厚 Harness 过载"问题。传统 Harness 的策略选择逻辑通常是硬编码的规则（如"错误次数 > N 则切换策略"）——这正是"框架驱动的认知"的典型症状。元控制器和 RL 自适应机制的兴起，代表了将这部分认知负载从 Harness **推回模型内生能力**的具体技术路径。Harness 的角色从"策略决策者"转变为"策略执行基础设施"——提供 LoopStrategy 抽象，但不决定何时使用何种策略。

## 4. 2025–2026 年行业动态

理论研究的突破正迅速传导至产业界，三大巨头采用不同技术路线探索策略自适应 [[60]]：

| 公司 | 技术路线 | 核心特征 |
|------|----------|----------|
| **Google DeepMind** | 基于演示学习 / 重复执行 | 通过观察人类演示或大量模拟执行内隐学习策略选择；数据驱动，不依赖显式元控制器 |
| **OpenAI** | 系统级 GUI Agent 强化学习 | 在操作系统级别通过 RL 端到端训练通用决策模型；策略选择是端到端学习的副产品 |
| **Anthropic** | 封装为可调用"技能" (Skills) | 将 ReAct、文档总结等复杂能力封装为独立技能；策略选择转化为"技能选择"问题；模块化，可解释性强，易扩展 |

三种路径的共同点：都试图摆脱静态的、基于提示的 Agent 行为控制，寻求更动态、可学习的自适应机制。元控制器和 RL 正是实现这些路径的核心技术组件。

2025–2026 年是 AI Agent 从"副驾驶"（Copilot）形态向"自主执行者"（Autonomous Executor）演变的关键时期 [[61]][[62]][[63]]。一个"副驾驶"可能精通某一种策略，但一个"自主执行者"必须是在多种策略间无缝切换的多面手。

## 5. 挑战、风险与未来展望

### 5.1 当前技术挑战

1. **元控制器的训练与泛化**：训练数据难以覆盖足够多样化的任务场景；在一个领域训练出的元控制器泛化到完全不同的领域的能力有待验证
2. **奖励函数设计的复杂性**：好的奖励函数需精确量化任务成功、效率、资源消耗乃至决策"优雅"程度——设计通用奖励函数几乎不可能
3. **"决策黑盒"问题与可解释性**：元控制器或 RL 策略本身若是复杂黑盒模型，即使底层 ReAct 等策略可解释，整个系统的决策逻辑依然模糊——对于金融、医疗等高风险领域是致命缺陷 [[65]]
4. **计算开销与延迟**：元决策过程本身消耗计算资源并引入延迟——需精细权衡收益与开销
5. **策略库的管理与扩展**：新策略不断被提出，如何动态整合并让元决策模块学会何时使用它们，仍是待解问题

### 5.2 潜在风险

1. **自主决策失控**：以"效率"为主要奖励的元控制器可能在没有充分安全检查的情况下选择高风险策略 [[66]]
2. **策略固化与局部最优**：RL 训练中策略选择模型可能过早收敛——发现大多数情况下 ReAct 效果"还不错"就懒于探索更优方案

### 5.3 未来方向

1. **更通用的元控制器框架**：像操作系统管理进程一样管理可动态增删的策略库，学习通用的策略评估和选择函数
2. **零样本 / 少样本的策略学习**：引入新策略时无需大量重新训练，通过阅读描述或少量演示快速理解适用场景
3. **RLHF-Meta**：将人类偏好引入元控制器训练循环——人类监督者对 Agent 的"策略选择"行为进行评价和修正 [[66]]
4. **与多智能体协作的结合**：在多智能体系统中，元控制器不仅是"自我管理者"，还需成为"社交策略家"——根据团队成员行为动态调整自身策略
5. **可解释元决策（Explainable Meta-Decision）**：元控制器在做出策略选择的同时生成可解释理由——"因为检测到任务环境存在高度不确定性，且已连续两次行动失败，我决定从 Plan-and-Execute 切换到 ReAct"
