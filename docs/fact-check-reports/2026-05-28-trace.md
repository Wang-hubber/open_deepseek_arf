## Finding 1 (Medium): EventType literal missing 8 types from the doc table

**Doc section**: 2.2 — Event Model, event type table
**Claim**: The table lists the event types supported by the framework
**Actual**: The `EventType` Literal in `arf/core/events.py` contains 8 additional event types not mentioned anywhere in the table or surrounding text:

| Missing Type | Domain | Since |
|-------------|--------|-------|
| `agent_switch` | A2A handoff | Present in code |
| `undo_executed` | Interrupt/Rollback | Present in code |
| `rollback_executed` | Interrupt/Rollback | Present in code |
| `rate_limited` | Protection (TODO #10) | Present in code |
| `circuit_opened` | Protection (TODO #10) | Present in code |
| `circuit_half_open` | Protection (TODO #10) | Present in code |
| `circuit_closed` | Protection (TODO #10) | Present in code |
| `breaker_blocked` | Protection (TODO #10) | Present in code |

**Impact**: Documentation is stale. Readers using the doc table as a reference will not know these event types exist. The trace viewer HTML (`trace_viewer.html`) already handles `rate_limited` and `circuit_opened` in its stats rendering, confirming these are active in the runtime.

**Recommendation**: Add the 8 missing types to the event type table in `docs/trace.md`. Protection events can be grouped as "Protection (when enabled)" with a note that they appear when the protection module is active.

## Finding 2 (Low): Non-testable claim about volume reduction

**Doc section**: 2.3 — FileTraceStore
**Claim**: "过滤后文件体积减少约 75%" (Filter reduces file volume by ~75%)
**Status**: Cannot be verified from code alone. This is an empirical claim about runtime behavior that depends on event distribution (ratio of filtered vs unfiltered events), which varies per session.

**Recommendation**: Either:
- Remove the percentage (keep the qualitative claim that filtering reduces volume), or
- Add a note that the percentage is approximate and depends on session characteristics.
