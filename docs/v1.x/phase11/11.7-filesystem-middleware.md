# Phase 11 / 11.7 — `FilesystemMiddleware` Filesystem/Backend Middleware

> **Task**: 实现 `FilesystemMiddleware` —— 基于 `BackendProtocol` 暴露文件系统工具给模型。
> **Gap addressed**: G-02（Middleware 钩子的第一个真实实现）+ G-10（per-request tool 可见性裁剪）
> **Source**: `docs/v1.x/phase10/99-gap-summary-recommendations.md` §3 G-02, G-10
> **Reference**: DeepAgents `FilesystemMiddleware` —— `libs/deepagents/deepagents/middleware/filesystem.py`
> **Status**: 📝 Doc — awaiting user Gitee 精校

---

## 1. Motivation

`Middleware` trait（11.6）已建立，但还没有真实实现。`FilesystemMiddleware` 是 **第一个也是最核心的 middleware**：
- 把 backend 的 6 个核心操作（ls / read / write / edit / glob / grep）作为工具暴露给模型
- 在每次 model_call 时改写 system prompt，描述可用 backend 能力
- 基于 `arf-backend::BackendProtocol`，可工作在任何 backend（State / Filesystem / Composite）

DeepAgents 的 FilesystemMiddleware 是它整个工具层的核心 —— 6 个工具 + 后端能力描述。

**本任务目标**：实现 ARFV1 等价的 FilesystemMiddleware。

---

## 2. Scope

### ✅ In scope

1. `FilesystemMiddleware` 实现 `Middleware` trait
2. 在 `before_model_call` 中：
   - 注入 6 个 `ToolSpec`（ls / read_file / write_file / edit_file / glob / grep）
   - 追加 system message 描述 backend capabilities
3. 接受 `Arc<dyn BackendProtocol>` 作为 backend
4. 接受可选工具过滤器（allow / deny list）
5. 完整测试

### ❌ Out of scope（11.8 或后续 task）

- 工具**执行**（BackendToolNode 把 tool_call 路由到 backend）—— M2 后续
- FilesystemPermissionInterrupt（→ G-14 / Phase 13）
- SummarizationMiddleware（→ M3）

## 3. 完整代码

### 3.1 `crates/arf-engine/src/middleware/filesystem.rs`

```rust
//! `FilesystemMiddleware` — exposes BackendProtocol ops as tools (Phase 11 / 11.7).
//!
//! Wraps an `Arc<dyn BackendProtocol>` and, in `before_model_call`:
//! 1. Injects 6 tool specs (ls / read_file / write_file / edit_file / glob / grep)
//! 2. Appends a system message describing backend capabilities
//!
//! **Tool execution** is NOT done by this middleware — it only injects the
//! declarations. A separate `BackendToolNode` (Phase 11-M2 subsequent task)
//! handles `tool_exec` routing. Until then, the model can see the tools but
//! calls to them will fail at the Engine's tool registry.

use std::sync::Arc;

use arf_backend::{BackendError, BackendPath, BackendProtocol};
use arf_core::{Middleware, ModelRequest, State, ToolSpec};
use async_trait::async_trait;
use serde_json::{json, Value};

/// Names of the 6 standard filesystem tools injected by this middleware.
pub const FS_TOOL_LS: &str = "ls";
pub const FS_TOOL_READ: &str = "read_file";
pub const FS_TOOL_WRITE: &str = "write_file";
pub const FS_TOOL_EDIT: &str = "edit_file";
pub const FS_TOOL_GLOB: &str = "glob_files";
pub const FS_TOOL_GREP: &str = "grep_files";

/// Filesystem middleware — exposes backend ops as model tools.
pub struct FilesystemMiddleware {
    backend: Arc<dyn BackendProtocol>,
    /// Optional allow-list (tool name → keep). `None` means all 6 tools.
    allowed: Option<Vec<String>>,
    /// Optional deny-list (tool name → remove).
    denied: Vec<String>,
}

impl FilesystemMiddleware {
    /// Create with default tool set (all 6 tools).
    pub fn new(backend: Arc<dyn BackendProtocol>) -> Self {
        Self {
            backend,
            allowed: None,
            denied: vec![],
        }
    }

    /// Restrict to a specific allow-list of tool names.
    pub fn with_allowed(mut self, names: Vec<String>) -> Self {
        self.allowed = Some(names);
        self
    }

    /// Add a tool name to the deny list.
    pub fn deny(mut self, name: impl Into<String>) -> Self {
        self.denied.push(name.into());
        self
    }

    /// Borrow the wrapped backend.
    pub fn backend(&self) -> &Arc<dyn BackendProtocol> {
        &self.backend
    }

    /// Build the 6 standard tool specs.
    fn standard_tools(&self) -> Vec<ToolSpec> {
        let all = vec![
            (
                FS_TOOL_LS,
                "List files and directories at a backend path.",
                json!({
                    "type": "object",
                    "properties": {
                        "path": {
                            "type": "string",
                            "description": "Backend path to list, e.g. '/workspace'"
                        }
                    },
                    "required": ["path"]
                }),
            ),
            (
                FS_TOOL_READ,
                "Read file contents with optional line range.",
                json!({
                    "type": "object",
                    "properties": {
                        "file_path": {
                            "type": "string",
                            "description": "Absolute backend path of the file"
                        },
                        "offset": {
                            "type": "integer",
                            "description": "0-indexed line offset (default 0)"
                        },
                        "limit": {
                            "type": "integer",
                            "description": "Maximum lines to read (default 2000, 0 = all)"
                        }
                    },
                    "required": ["file_path"]
                }),
            ),
            (
                FS_TOOL_WRITE,
                "Write content to a file, creating or overwriting it.",
                json!({
                    "type": "object",
                    "properties": {
                        "file_path": {
                            "type": "string",
                            "description": "Absolute backend path"
                        },
                        "content": {
                            "type": "string",
                            "description": "Content to write"
                        }
                    },
                    "required": ["file_path", "content"]
                }),
            ),
            (
                FS_TOOL_EDIT,
                "Exact-string replacement in an existing file.",
                json!({
                    "type": "object",
                    "properties": {
                        "file_path": { "type": "string" },
                        "old_string": { "type": "string" },
                        "new_string": { "type": "string" },
                        "replace_all": {
                            "type": "boolean",
                            "description": "Replace all occurrences (default false)"
                        }
                    },
                    "required": ["file_path", "old_string", "new_string"]
                }),
            ),
            (
                FS_TOOL_GLOB,
                "Find files matching a glob pattern.",
                json!({
                    "type": "object",
                    "properties": {
                        "pattern": {
                            "type": "string",
                            "description": "Glob pattern, e.g. '**/*.rs'"
                        },
                        "base": {
                            "type": "string",
                            "description": "Optional base directory"
                        }
                    },
                    "required": ["pattern"]
                }),
            ),
            (
                FS_TOOL_GREP,
                "Search for a literal text pattern in files.",
                json!({
                    "type": "object",
                    "properties": {
                        "pattern": { "type": "string" },
                        "path": { "type": "string" },
                        "glob_filter": { "type": "string" }
                    },
                    "required": ["pattern"]
                }),
            ),
        ];

        all.into_iter()
            .filter(|(name, _, _)| match &self.allowed {
                Some(allow) => allow.iter().any(|a| a == name),
                None => true,
            })
            .filter(|(name, _, _)| !self.denied.iter().any(|d| d == name))
            .map(|(name, desc, params)| ToolSpec::new(name, desc, params))
            .collect()
    }

    /// Build the system-prompt suffix describing backend capabilities.
    fn capabilities_text(&self) -> String {
        format!(
            "\n\n# Filesystem Backend\n\n\
            You have access to a backend with these operations:\n\
            - `ls(path)`: list directory entries\n\
            - `read_file(path, offset?, limit?)`: read file content with line range\n\
            - `write_file(path, content)`: create or overwrite file\n\
            - `edit_file(path, old, new, replace_all?)`: exact-string replace\n\
            - `glob_files(pattern, base?)`: find files by glob pattern\n\
            - `grep_files(pattern, path?, glob_filter?)`: search file contents\n\n\
            All paths are absolute backend paths starting with `/`.\n\
            Use these tools to interact with the user's workspace."
        )
    }
}

#[async_trait]
impl Middleware for FilesystemMiddleware {
    fn name(&self) -> &str {
        "filesystem"
    }

    async fn before_agent(&self, _state: &State) {
        // One-shot setup: nothing to do here (backend already wrapped).
    }

    async fn before_model_call(&self, ctx: &mut ModelRequest, _state: &State) {
        // Inject the 6 standard tools (subject to allow/deny lists).
        for tool in self.standard_tools() {
            ctx.add_tool(tool);
        }
        // Append capabilities suffix.
        ctx.extend_system_suffix(self.capabilities_text());
    }
}

// ---------------------------------------------------------------------------
// Helper for BackendPath validation in tool calls
// ---------------------------------------------------------------------------

/// Parse a string from a tool call into a `BackendPath`, returning a
/// user-friendly error message if the path is malformed.
pub fn parse_backend_path(raw: &str) -> Result<BackendPath, String> {
    BackendPath::new(raw).map_err(|e| format!("{e}"))
}

// ---------------------------------------------------------------------------
// Future: BackendToolExecutor (stub for M2 follow-up)
// ---------------------------------------------------------------------------
//
// The actual tool_exec wiring requires a `BackendToolNode` that advertises
// itself on the bus with the 6 tool capabilities. When the model emits a
// `tool_call` for one of these names, the bus routes it to BackendToolNode,
// which dispatches to the wrapped backend.
//
// This is planned for the next task (11.8) once FilesystemMiddleware lands.

/// Internal: helper for downstream `BackendToolExecutor`.
pub(crate) fn backend_error_to_json(e: BackendError) -> Value {
    json!({
        "error": e.to_string(),
        "code": e.code(),
    })
}
```

## 4. 逐行解释

### 4.1 6 个标准工具

```rust
const FS_TOOL_LS: &str = "ls";
const FS_TOOL_READ: &str = "read_file";
// ...
```

工具名遵循 DeepAgents 约定（`ls` / `read_file` / `write_file` / `edit_file` / `glob_files` / `grep_files`）。`glob_files` 加后缀 `_files` 避免与未来 `glob` builtin 冲突。

### 4.2 参数 schema

每个工具的 JSON Schema 与 `BackendProtocol` 方法签名一致：
- `read_file(file_path, offset, limit)` — `offset`/`limit` 可选（DeepAgents 默认 2000）
- `edit_file(file_path, old, new, replace_all)` — `replace_all` 默认 false
- `glob_files(pattern, base?)` — `base` 可选

LLM 通过 tool_call JSON 直接传参，参数校验由 JSON Schema 完成。

### 4.3 allow / deny 过滤

```rust
let all = vec![ ... ];
all.into_iter()
    .filter(|(name, _, _)| match &self.allowed {
        Some(allow) => allow.iter().any(|a| a == name),
        None => true,
    })
    .filter(|(name, _, _)| !self.denied.iter().any(|d| d == name))
    .map(...)
```

支持：
- 默认（无 allowed/denied）→ 全部 6 个工具
- `with_allowed(vec!["read_file"])` → 只读
- `deny("write_file")` → 移除单个工具

这直接对应 Phase 10 G-10（per-request tool 可见性裁剪）。

### 4.4 system prompt 注入

```rust
ctx.extend_system_suffix(self.capabilities_text());
```

不覆盖 system template；只在末尾追加 capabilities 段。这样：
- 应用自带的 system_prompt_template 保留
- 模型看到一致的能力描述

### 4.5 `parse_backend_path` helper

```rust
pub fn parse_backend_path(raw: &str) -> Result<BackendPath, String> {
    BackendPath::new(raw).map_err(|e| format!("{e}"))
}
```

BackendToolNode（未来 11.8）会调用此函数把 LLM 传入的 string 转为 BackendPath，统一错误格式。

## 6. 与 DeepAgents FilesystemMiddleware 的差异

| 维度 | DeepAgents | ARFV1 | 原因 |
|------|------------|-------|------|
| 工具名 | `ls` / `read_file` / `write_file` / `edit_file` / `glob` / `grep` | `ls` / `read_file` / `write_file` / `edit_file` / `glob_files` / `grep_files` | 避免 builtin 冲突 |
| 后端协议 | BackendProtocol ABC | arf-backend::BackendProtocol trait | Rust 风格 |
| Backend 选择 | 多个 + Composite | 同 | 一致 |
| 工具执行 | middleware 内置 execute_tool | 待 BackendToolNode（11.8） | ARF 走 bus |
| 文件 sandbox | 每个 backend 独立 | 同 | 一致 |

---

## 7. 不破坏 ARFV1 现有优势

1. **Middleware 钩子层** — FilesystemMiddleware 是 Middleware trait 的**用户**，不破坏 trait
2. **Backend 抽象** — FilesystemMiddleware 直接用 11.1 的 `BackendProtocol`
3. **Bus 多 runtime** — FilesystemMiddleware 与 McpNode 并存（BackendToolNode 11.8 会有 bus 集成）
