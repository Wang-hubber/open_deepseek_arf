### Agent 产品高强度用户，对模型行为有品味有判断力

**匹配度：✅ 强证据**

ARF 的设计决策透露出对 Agent 行为的深度理解：

- **三层记忆系统**：会话内 + 跨会话 + 归档，说明理解 Agent 记忆的真实痛点（不是简单的"存下来"，而是"什么该记、什么时候忘、怎么检索"）
- **动态模型路由**：任务复杂度自动分类 → quick/deep 模型切换，说明理解"不是所有任务都需要最强模型"
- **Hook 引擎**：退出码契约（0/1/2），崩溃不拖垮 Agent——说明被"Hook 挂了 Agent 也挂了"这个问题毒打过
- **技能流水线**：DFS 环检测 + 有序执行——说明理解工具调用的编排需求
- **SlidingWindowCompactor**：基于真实 token 使用量触发，不是拍脑袋的阈值

这些不是"看了论文实现的"，而是**用了大量 Agent 产品后提炼出来的工程直觉**。

## 四、ARF 项目与 Harness 职位的深度契合

这个职位描述中的关键句：

> "Model + Harness = Agent。这其中除模型本身以外的所有工作，都属于 Harness 的范畴。"

ARF 的定位几乎就是这句话的回声：

| Harness 职责 | ARF 对应模块 | 深度 |
|-------------|-------------|------|
| 执行层设计 | `GraphEngine`（1195 行）— Agent Loop 核心 | 深 |
| 工具系统 | `ToolProvider` + `ToolResolver` + `FunctionBackend` + `ConcurrentToolExecutor` | 深 |
| 上下文管理 | `SlidingWindowCompactor` + 提示词管道 + 动态注入 | 中 |
| 记忆系统 | 双轨记忆（规则+LLM）+ 三级存储 + 检索 | 深 |
| 安全防护 | PathSandbox → PathCheckToolGuard → ToolPermissionChecker → HumanApproval | 深 |
| 模型路由 | `TwoTierRouter` — 任务复杂度分类 + 模型切换 | 中 |
| 可观测性 | FileTrace + OtelTracer + ReplayController + UsageTracker | 中 |
| 智能体自演进 | `resource_scaffold` + `file_writer` — Agent 可自行创建新工具 | 创新点 |
| 多智能体通信 | `AgentBus` + `Supervisor` + `SharedWorkspace` + `Lock` + `Consensus` | 中 |
| 技能编排 | `SkillPipeline` — DFS 依赖图 + 有序执行 | 中 |

ARF 的每一个模块都直接对应 Harness 的一项核心职责。这不是"做了一个 Agent 应用"，而是"做了一套 Agent 基础设施"。

## 五、简历的叙事优势

### 亮点

1. **跨领域演进路径清晰**：车辆工程 → 数据 → 算法 → Agent → 框架，不是乱跳而是逐层下探
2. **ARF 项目定位精准**：简历没有写"我用 LangChain 搭了一个客服机器人"，而是清晰表达了**设计哲学（约定大于配置）、技术决策（控制层与执行层解耦）、创新理念（Agent 自演进）**
3. **量化成果丰富**：业务效率提升 35%、响应时间缩短 42%、推理成本降低 27%、用户活跃度增长 70%、算法准确率 90%
4. **直接对接 DeepSeek 技术栈**：简历中明确提到 DeepSeek 全系列模型、动态路由策略，技术栈与目标公司高度重合

### 叙事中的潜在弱点

1. **车辆工程本科背景**：在一些看重 CS 科班的团队中可能被视为劣势，但 9 年跨领域实战经验 + 开源框架 + 算法比赛可以很大程度上弥补。如果面试中被问到，不要回避——"非科班逼我学得更深"是一个有力的叙事角度
2. **最近两份工作都不到一年半**：大众安徽 ~2 年（2023.08-至今），山东国金 ~10 个月（2022.10-2023.07）。如果被问到，建议正面回应：国金时期可能是受汽车行业下行影响，大众安徽则是找到了真正的方向
3. **没有论文发表**：这个职位要求"与研究员深度协作"，缺乏学术背景可能是一个短板。但可以通过"我在大众安徽做的 LLM-as-a-Judge 评估流水线就是面向模型效果的研究实践"来弥补
4. **开源项目是 solo**：ARF 的代码有 solo 开发者的特征（代码重复、全局变量等），如果被问"你的代码 review 流程是什么"，需要坦诚说明这是个人项目

## 六、面试策略建议

### 核心叙事线

> "我是一个从机械背景出发、花了十年时间逐步深入计算机科学核心的工程师。我的优势不是某一个技术点，而是**能从框架设计的高度理解 Agent 系统的每一个部分如何协同工作**——因为我独立设计并实现了整个系统。"

### 必聊话题

- **为什么选择文件系统作为资源管理媒介**——这是个有深度的架构决策，面试官会对 trade-off 感兴趣
- **invoke() 和 astream() 的 700 行重复代码**——主动提出来，说明你意识到这个问题并打算重构。反思能力比完美代码更重要
- **ARF 和 LangChain/Dify 的本质区别**——你已经在简历中提到了，面试中会被深挖
- **大众安徽的 Multi-Agent 系统**——这是你最近的生产环境经验，最接近 DeepSeek 的实际工作

### 可能的压力测试

- "你一个车辆工程毕业生，凭什么认为自己能做 Agent 基础设施？"
  - 回应：不回避，正面讲述跨领域学习的方法论和 ARF 的架构细节
- "ARF 比 LangChain 强在哪？你凭什么说别人过度抽象？"
  - 回应：不要攻击竞品，聚焦"不同的设计选择适用于不同的场景"
- "你的代码质量不够工程化（全局变量、重复代码）"
  - 回应：坦诚承认，说明这是个人项目的权衡（速度 > 完美），在团队中你的标准会不同
